PigeonStack：Codex 多 Agent 协作工作流

首先致敬并感谢 Lauren Tan（poteto），她是 pstack 的原作者。PigeonStack 基于她的工作，为 Codex 流程做了适配。

PigeonStack 是 PigeonYang 维护的 Codex 工作配置，包含全局规则、适配后的 pstack 插件、Agent 角色定义、选定配置和本地同步脚本。Sol 负责决策，Astra 提供疑难问题建议，Luna 执行明确的任务。

预览或安装 阅读中文 README

目标是兼顾能力与成本的协作方式。仓库没有经过测量的速度、节省金额或跑分领先承诺。

明确交接边界

由一位主控负责决策

主控检查证据、选择方案并验收结果。子 Agent 接收范围明确的任务，带回改动、观察结果或阻塞原因。

角色职责
Sol 主控负责理解目标、诊断、关键决策、任务拆分、子 Agent 调度、集成安排和最终验收。
Astra 顾问根据关键证据回答一个尚未解决的问题。顾问只读，并给出不确定性和有限的验证路径。
Astra 文档作者或调查者使用单独的执行角色撰写权威技术文档，或对一个未解决问题开展只读调查。
Luna 执行者实现主控选定的修复或已认可的设计步骤，按明确清单只读采集证据，或运行指定检查。无法解释的失败交回主控。

这些是仓库中的角色约定。任务规模本身不会把实现工作转给 Astra。主控先选定方案，再由 Luna 执行范围明确的步骤。实际模型路由和可用性取决于 Codex 宿主与账号；用户明确选择的模型优先于默认值。

并行执行彼此独立的工作

没有共用写入或依赖的文字与代码任务可以并行。生图、图片编辑、查看和传输一次只处理一项。

使用 Codex 已有的能力

PigeonStack 打包了指令、Codex 插件、配置和部署工具。它不提供 MCP 服务或单独的自主调度器。

没有其他独立工作可做时，主控会等待委派任务，最长 30 分钟。等待可中断，收到事件后会提前返回。首次委派满 30 分钟时，主控会对未解决工作做一次评估。更换执行者不会重置计时。

执行者报告无法解决任务时，主控会让一位新的 Astra 顾问以 high 推理强度只读调查一个问题。30 分钟评估发现任务仍未解决时，主控也会这样做。顾问报告无法解决，或在其自己的 30 分钟评估时问题仍未解决，主控会启动一位新的顾问，并提高到下一级推理强度。Astra 模型保持不变，推理强度依次为 high、xhigh、max、ultra。顾问只读并提出方案。主控接受方案后，才交由 Luna 执行。所需推理强度不可用时，主控会报告限制，不会静默降级。若 ultra 仍无法解决，则返回具体阻塞原因或缺失证据。已确认健康的长时间命令继续按现有观察循环运行。凭据、访问、权限或服务不可用属于外部阻塞，不是推理失败。模型 ID 和角色详情见 MODELS.md。

只有在已确认当前问题或存在明确的当前要求时，才添加校验门。修复场景要先确认并诊断问题；仅凭未来可能失败的猜测不够。校验门应限于受影响的操作和边界。验证它能捕获已确认的问题或落实当前要求，同时不无故阻断正常操作。

适用人群

适合需要清晰交接的 Codex 用户

如果你需要明确的决策负责人、范围清楚的执行任务和基于证据的验收，可以了解 PigeonStack。

兼顾成本与能力是工作策略，不是跑分结论。模型 ID、账号权限、支持的推理强度和费用取决于你的账号与 Codex 客户端。

当前宿主要求

  • 维护中的配置已在 Windows 与 PowerShell 环境验证。
  • 同步脚本要求 Python 3.11 或更高版本。
  • 安装插件需要兼容的 Codex CLI，以及已注册并能解析 pstack@personal 的本地插件市场。
  • 多 Agent 工作需要宿主提供原生子 Agent 工具，并且账号可使用所选模型。

常见问题与边界

使用前需要了解什么

PigeonStack 是什么？

PigeonStack 是 PigeonYang 维护的一套 Codex 全局规则、Agent 角色定义、选定配置、定制版 pstack 插件和本地同步脚本。

PigeonStack 与 pstack 有什么关系？

PigeonStack 将 Lauren Tan 的 pstack 工作流适配到 Codex，并加入本仓库的规则和部署配置。它不宣称优于上游项目。页面链接到固定版本的上游源码，并保留原作者署名。

它是插件、MCP 服务还是 Skill？

PigeonStack 是一个代码仓库和部署配置，内含适配后的 Codex 插件与选定技能。它不提供 MCP 服务、定时任务、钩子或后台调度器。

可以选择其他模型吗？

仓库支持配置模型选项，本地规则也规定用户明确选择优先。你的 Codex 宿主和账号必须提供所选模型与 Agent 工具。仓库不验证服务商内部的模型映射。

预览和安装有什么区别？

独立预览使用 --codex-home 和 --skip-plugin-install 检查文件副本与配置合并。它不会激活插件，也不会改写指令中机器专属的路径。请看开始使用指南了解两种流程。

哪些结果经过验证？

同步检查成功表示受管理文件与配置在磁盘上保持一致。要确认指令已加载和实际模型路由，还需在新的 Codex 会话中验证。发布本网站不能证明搜索引擎已收录或页面获得排名。
