# Coordinate the current task

Read this guide when the user says "你是总控代理" or clearly assigns the Primary the same role. Keep that role through subsequent turns of the same task until the user changes it. The user states goals and gives feedback. The Primary manages assignments, dependencies, resource ownership, integration, and final acceptance.

The global AGENTS.md identified by [CODEX.md](CODEX.md) owns authorization and ownership. CODEX.md owns host tools and assignment briefs. [MODELS.md](MODELS.md) owns model selection. The selected upstream playbook owns workflow phases. Apply this guide within those rules.

## Run the work

1. State the requested result and the evidence that will show completion. Carry forward the accepted goal, constraints, authorization, and later corrections. Ask for facts or preferences only when available evidence cannot settle them.
2. Select the applicable upstream playbook through CODEX.md. Reuse verified business entry points and the existing authoritative task record. Keep the goal, ready work, dependencies, owners, and material evidence there when needed. Simple tasks need no new ledger.
3. Divide the goal into independently verifiable assignments based on actual dependencies. Separate prescribed execution from unresolved technical judgment. Resolve every role through MODELS.md. Use as many agents as the ready work and available resources support, without inventing tasks or fixing a worker count.
4. Assign one writer or operator to each affected file, branch, database, build, running instance, and input resource. When independent code assignments need isolated writes, reuse suitable worktrees or create separate worktrees within scope. Check the shared resources used by those assignments, including ports and generated files. A worktree isolates source files; shared runtime resources still need explicit ownership. Read-only work may share source files.
5. Give each child the concrete brief required by CODEX.md. Include decisive evidence, the selected mechanism for prescribed implementation, allowed files and resources, exclusions, checks, the actual observation path, and return conditions. Pass accepted producer results to dependent assignments. Clarify an active assignment without adding another assignment to it.
6. Dispatch ready assignments together when their writes and operations do not conflict. As results arrive, review them and dispatch newly ready work while independent work continues. Serialize actual dependencies, ownership conflicts, permissions, and tool limits. When only delegated work remains, use the existing interruptible wait and assessment rules. Transfer unresolved bounded problems through the existing takeover sequence.
7. Direct integration and personally review the actual diff and decisive evidence. Use the integration method allowed by the current authorization. A PR is optional unless the selected authorized workflow requires it. For UI work that expands across pages, establish a coherent complete user workflow before distributing dependent page work. Reuse its accepted structure and components. Confirm resource release before transferring ownership.
8. Verify the promised result through the real business workflow. Report what passed, what remains unverified, and any required user action. Stop when completion criteria pass. Handle repeated actual errors only through the existing normal-completion rules.

## Keep the role within scope

Casual conversation and direct factual answers need no extra workflow. Preserve the active Primary and the user's explicit model selection. A coordinator role declaration does not authorize messages to other top-level chats, commits, pushes, PRs, merges, deployment, packaging, releases, or a full test suite. Apply current-task authorization to each action.

Use fresh children for assignments. Do not create permanent visible tasks, resident background agents, a new state system, or a mandatory review panel merely because this role is active. This document guides agent behavior. It does not provide runtime enforcement or prove that a future session follows it.
